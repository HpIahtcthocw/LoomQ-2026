# LoomQ-Q：量子 RISC-V 自定义扩展指令规格 v1.0

> 对应赛题 Bonus「自定义量子 RISC-V 扩展指令（+8）」交付物 ①：指令编码规格文档。
> 交付物 ② 扩展实现见 `tools/riscv_quantum_emulator.py`；
> 交付物 ③ 端到端测试见 `tools/selftest_quantum_ext.py`。

## 1. 这套扩展要解决什么

L3 的产物是**两份互不相识的东西**：一个量子操作序列，一份经典 RISC-V 汇编。
两者在评测时分开验证——汇编跑在 `riscv_emulator.py` 上，量子部分跑在模拟器上。
但真实的混合程序里，两者是有数据依赖的：测量结果要立刻决定后续经典分支，
经典计算的结果也可能反过来决定后续施加哪个门。

LoomQ-Q 把量子操作编码成 RISC-V 自定义指令，于是**两者进入同一条指令流、
在同一台机器上按顺序执行**：`q.meas` 把测量塌缩的结果直接写进通用寄存器，
下一条 `beq` 立刻就能用它跳转。这是这套扩展存在的唯一理由。

## 2. opcode 选择

RISC-V 规范为非标准扩展保留了四段 opcode。本扩展占用 **custom-0**：

```
opcode = 0b0001011 = 0x0B
```

选 custom-0 而不是自造一个未分配的 opcode，是为了不与任何标准扩展冲突：
`0b0001011` 在 RV32I/RV64I 及已批准的标准扩展里均未使用。

## 3. 指令格式

沿用 RISC-V **R-type** 的字段划分，不新增字段宽度，这样现成的取指/译码
流水线不用改数据通路：

```
 31        25   24    20   19    15   14  12   11     7   6      0
┌────────────┬──────────┬──────────┬────────┬──────────┬──────────┐
│   funct7   │   rs2    │   rs1    │ funct3 │    rd    │  opcode  │
│   7 bits   │  5 bits  │  5 bits  │ 3 bits │  5 bits  │  7 bits  │
└────────────┴──────────┴──────────┴────────┴──────────┴──────────┘
```

`funct3` 选操作类别，`funct7` 选具体门。**5 位字段既可以放寄存器号，
也可以放量子比特下标**，具体含义由 `funct3` 决定——这是本扩展唯一偏离
标准 R-type 语义的地方，下表逐条说明。

比特下标用立即数而非寄存器值，因为 OpenQASM 里门作用的比特是静态确定的，
没有"运行期算出要操作哪个比特"的需求；用立即数省掉一次寄存器读。
5 位宽 ⇒ 最多寻址 32 个量子比特，与 32 个通用寄存器对齐。

### 3.1 funct3 操作类别

| funct3 | 助记符 | 语义 | rs1 | rs2 | rd |
|---|---|---|---|---|---|
| `0b000` | `q.gate` | 施加非参数门 | 比特下标 | 比特下标 | 比特下标 |
| `0b001` | `q.gatep` | 施加参数门 | 比特下标 | 比特下标 | **寄存器号**，其值为定点角度 |
| `0b010` | `q.meas` | 测量并塌缩 | 比特下标 | 忽略（填 0） | **寄存器号**，接收 0 或 1 |
| `0b011` | `q.init` | 复位到 \|0⟩ | 比特下标 | 忽略（填 0） | 忽略（填 0） |

未用到的字段一律填 0。解码器会校验这些字段确实为 0，不容忍垃圾位——
宁可报错也不要静默执行成别的指令。

### 3.2 funct7 门编号

高位按元数分段，解码时可据此校验操作数个数：

| funct7 | 门 | 元数 | 参数 |
|---|---|---|---|
| `0x00` | `h` | 1 | — |
| `0x01` | `x` | 1 | — |
| `0x02` | `s` | 1 | — |
| `0x03` | `sdg` | 1 | — |
| `0x04` | `t` | 1 | — |
| `0x05` | `tdg` | 1 | — |
| `0x10` | `cx` | 2 | — |
| `0x11` | `swap` | 2 | — |
| `0x20` | `ccx` | 3 | — |
| `0x40` | `ry` | 1 | θ |
| `0x41` | `rz` | 1 | θ |
| `0x50` | `cu1` | 2 | θ |

这 12 个门正是赛题第三节的白名单，与 L1 转译层用的是同一张表。
`0x00–0x0F` 段留给单比特非参数门，`0x10–0x1F` 双比特，`0x20–0x2F` 三比特，
`0x40+` 带参数——分段留了扩展余量。

### 3.3 定点角度表示

参数门的角度不放在指令里，而是放在 `rd` 指定的通用寄存器中，
按**定点**解释：

```
θ = value × π / 65536        （即 π/2^16 为单位，有符号）
```

理由有两条。一是 7 位的 `funct7` 已经被门号占满，塞不进有用精度的角度；
二是角度放寄存器里意味着**角度可以由经典代码算出来**——这恰好是混合
编程想要的能力，比编译期常量更有表达力。

单位取 π/2^16 的好处：QFT 里常见的 π/2^k（k ≤ 16）都能被**精确**表示，
不引入舍入误差。分辨率约 4.79×10⁻⁵ rad。

例：`rz(π/2)` ⇒ 寄存器值 `32768`；`cu1(π/8)` ⇒ `8192`；`ry(-π)` ⇒ `-65536`。

## 4. 汇编助记符

汇编器接受的文本形式（大小写不敏感，逗号可选）：

```asm
q.gate  h, 0                # H 作用在 q[0]
q.gate  cx, 0, 1            # CX 控制 q[0]，目标 q[1]
q.gate  ccx, 0, 1, 2        # CCX
q.gatep rz, 0, x5           # RZ(x5 × π/65536) 作用在 q[0]
q.gatep cu1, 0, 1, x6       # CU1(x6 × π/65536)
q.meas  0, x10              # 测量 q[0]，结果写入 x10
q.init  0                   # q[0] 复位到 |0>
```

原有 7 条经典指令（`li add sub addi beq bne j`）语法与语义完全不变。

|---|---|---|
| funct7 | `0x00`（h） | `0000000` |

## 6. 执行语义

### 6.1 机器状态

扩展后的机器在原有状态之外增加一项量子态：

- `registers[0..31]`：通用寄存器，`x0` 恒为 0（不变）
- `pc`、`labels`、`instructions`（不变）
- **`statevector`**：`2^n` 个复振幅，初始 `|0…0⟩`

### 6.2 各指令语义

- **`q.gate` / `q.gatep`**：按门号对 `statevector` 施加对应酉变换。
  酉变换的实现直接复用 L1 的参考模拟器 `loomq.refsim._apply_gate`，
  **不另写一套**——这样量子语义与 L1 判定用的是同一份代码，
  不存在"扩展模拟器算得跟参考模拟器不一样"的风险。
- **`q.meas`**：对指定比特做投影测量。按 `|振幅|²` 求出该比特为 1 的概率，
  抽样得到结果 0 或 1，**塌缩**态矢（把不一致的分量清零后重新归一化），
  再把结果写进 `rd` 指定的寄存器。写 `x0` 时按 RISC-V 惯例丢弃。
- **`q.init`**：先测量该比特，若结果为 1 则施加 `x` 门，从而无条件回到 \|0⟩。
  这样定义可以复用测量塌缩逻辑，且对处于纠缠态的比特也有正确定义。

### 6.3 确定性

测量涉及抽样，所以扩展模拟器接受一个 `seed`。给定种子后整机行为完全确定，
测试因此可复现。`q.meas` 之外的所有指令都是确定性的。

## 7. 与 L3 主体的衔接

`tools/riscv_quantum_emulator.py` 里的 `assemble_hybrid_program()` 把
`compile_hybrid()` 的两份产物缝成**一份**指令流：量子操作按原顺序编码成
自定义指令，`measure q[k] -> c[j]` 编码成 `q.meas k, x(10+j)`——
正好落在 L3 约定的测量位寄存器上，于是经典段生成的代码不用改一个字
就能读到测量结果。

端到端链路：

```
Hybrid-QASM
   └─ compile_hybrid()  →  量子操作序列 + 经典 RISC-V 汇编
         └─ assemble_hybrid_program()  →  单一混合指令流
               └─ 编码成 32 位机器码
                     └─ TinyQuantumRISCVEmulator 解码执行
                           └─ 量子态演化 + 测量塌缩 + 经典分支
```

## 8. 已知边界

诚实列出这套扩展**不做**什么：

- 比特下标 5 位宽，最多 32 个量子比特；态矢模拟实际上限更低（内存 `2^n`）。
- 没有量子寄存器重命名、没有比特分配器：下标就是物理下标。
- `q.gatep` 的角度精度受定点单位限制（π/2^16），非 π/2^k 的角度会有舍入。
- 不支持经典值反向控制**门的选择**（只支持控制门的**参数**）。
  要做到前者需要在指令流里对量子指令本身做分支，本扩展的指令编码支持
  （量子指令和 `beq` 在同一条指令流里，跳过一条量子指令是合法的），
  但没有为此设计专门的语法糖。
- 单指令单操作，没有向量化或并行门。
